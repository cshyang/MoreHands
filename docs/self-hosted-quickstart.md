# Minimal self-hosted quickstart

This is the smallest useful MoreHands setup: one Slack workspace, one GitHub
repository, one Cloudflare Worker deployment, and Nango-backed GitHub
connection capture. For the complete production deployment guide, see
[deployment.md](deployment.md).

## Minimum services

- Cloudflare account with Workers, D1, KV, Durable Objects, and Wrangler access.
- Slack workspace where you can create and install an app.
- Nango project with a GitHub integration enabled. For a single repository,
  `github-pat` is the narrowest path; `github-app-oauth` or `github` also work
  when your Nango project is set up for them.
- OpenRouter API key for Worker agent turns.
- GitHub access to the target repository. If you use `github-pat`, paste the PAT
  only into the Nango connection page that MoreHands posts in Slack.
- Node `>=22.18`, `npm`, `git`, and `wrangler` on the operator machine.

Minimum values in `.env.deploy`:

| Value | Where it comes from | Notes |
|---|---|---|
| `OPENROUTER_API_KEY` | OpenRouter | Required for agent turns. |
| `ADMIN_CONNECTIONS_TOKEN` | You generate it | Random string guarding admin routes. |
| `NANGO_SECRET_KEY` | Nango | Required to create/fetch connection sessions. |
| `NANGO_WEBHOOK_SECRET` | Nango | Required for `/nango/webhook` verification. |
| `SLACK_SIGNING_SECRET` | Slack app | Add after the Slack app exists. |
| `SLACK_BOT_TOKEN_DEFAULT` | Slack app install | `xoxb-...`; `setup.sh secrets` derives `SLACK_BOT_ID` and `KNOWN_TEAM_IDS`. |
| `HEARTBEAT_TOKEN` | Generated by `setup.sh secrets` if blank | Guards internal cron routes. |
| `D1_DATABASE_ID`, `KV_NAMESPACE_ID` | Generated by `setup.sh resources` | Account-local resource ids; leave blank before the first run. |

Linear and Trigger.dev are not required for this minimal Slack + GitHub read
setup. Add them later if you want Linear-triggered coding runs.

## Verify locally

Install dependencies and run the deterministic checks before touching any cloud
state:

```bash
npm ci
npm run typecheck
npm test
npm run build
```

For a local Worker loop, copy `.env.example` to `.dev.vars`, add a throwaway
model key, and run:

```bash
cp .env.example .dev.vars
$EDITOR .dev.vars
npx flue dev --target cloudflare
```

Local model calls can fail because of local egress or provider credentials. Use
the deployed Worker plus `./scripts/setup.sh doctor` for the final integration
check.

## Deploy the Worker

Log in to the Cloudflare account you want to host this instance:

```bash
wrangler login
cp .env.deploy.example .env.deploy
$EDITOR .env.deploy
```

Fill at least `OPENROUTER_API_KEY`, `ADMIN_CONNECTIONS_TOKEN`,
`NANGO_SECRET_KEY`, and `NANGO_WEBHOOK_SECRET`. Leave Slack values blank until
you create the app.

Run the Cloudflare phases:

```bash
./scripts/setup.sh resources
./scripts/setup.sh migrate
./scripts/setup.sh deploy
```

`deploy` writes `MOREHANDS_PUBLIC_URL` to `.env.deploy` when Wrangler reports the
Worker URL. Use that URL for external dashboard wiring:

- Slack events: `<worker-url>/slack/events`
- Slack commands: `<worker-url>/slack/commands`
- Nango webhook: `<worker-url>/nango/webhook`

Create or update the Slack app with the generated manifest:

```bash
./scripts/setup.sh manifest
```

Paste the output into the Slack app manifest, install the app to the workspace,
then copy the Slack signing secret and bot token back into `.env.deploy`:

```bash
SLACK_SIGNING_SECRET=...
SLACK_BOT_TOKEN_DEFAULT=xoxb-...
```

Push secrets and check the deployment:

```bash
./scripts/setup.sh secrets
./scripts/setup.sh doctor
```

The core deployment is healthy when `doctor` reports no failed core checks. It is
okay for optional Linear or runner lines to remain unchecked in this minimal
setup.

## Connect one GitHub repository

1. In Nango, enable the GitHub integration you plan to use. For a one-repo PAT,
   the expected integration key is `github-pat`.
2. Mention the bot in the Slack channel where the project should live. This
   creates the channel binding.
3. Ask for setup status and include the target repository:

   ```text
   @MoreHands setup status for owner/repo
   ```

4. If GitHub is missing, ask the bot to connect that repository:

   ```text
   @MoreHands connect GitHub PAT for owner/repo
   ```

5. Open the secure connection link posted by the bot and complete the Nango
   flow. MoreHands stores only connection metadata in D1; Nango stores the
   credential.
6. Ask `/hands status` or ask the bot for setup status again. The GitHub line
   should show as connected for the channel.

## Common failure modes

- `Missing .env.deploy`: copy `.env.deploy.example` and rerun the phase.
- `wrangler not logged in`: run `wrangler login` for the target Cloudflare
  account, then rerun `./scripts/setup.sh doctor`.
- D1 or KV ids are absent: run `./scripts/setup.sh resources`; the ids are
  written to `.env.deploy`, not tracked config.
- `POST /slack/events` is not `401` in `doctor`: the Worker URL is wrong, the
  Worker is not deployed, or `SLACK_SIGNING_SECRET` was not pushed with
  `./scripts/setup.sh secrets`.
- Slack auth fails: reinstall the Slack app, copy the new `xoxb-...` token into
  `.env.deploy`, and rerun `./scripts/setup.sh secrets`.
- GitHub connection link cannot be created: confirm `NANGO_SECRET_KEY` is set,
  the Nango webhook points at `<worker-url>/nango/webhook`, and the expected
  integration key (`github-pat`, `github-app-oauth`, or `github`) exists in
  Nango.
- GitHub looks connected but tools are missing: rerun `/hands status` in the
  channel and check `./scripts/setup.sh doctor`; the connection is scoped to the
  Slack channel that completed the Nango flow.
- Node or Flue errors during build: confirm `node --version` is `>=22.18`, then
  rerun `npm ci` and `npm run build`.
