# Flue 0.11 → 1.0 Migration Plan

**Historical reference (organized 2026-10-05):** This retained plan targets the superseded Flue 1.0 beta. Current production uses Flue 2.2.2; see the [completed cutover](../../operations/2026-10-05-flue-cutover.md). Its unchecked incremental-adoption proposals remain unverified. This document is not an active execution instruction or a completed-plan certificate.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move MoreHands from `@flue/{runtime,sdk,cli}@^0.11.0` to `1.0.0-beta.1` with no behavior change, then adopt 1.0's new capabilities incrementally.

**Architecture:** The version bump is *one atomic step* — you cannot run 0.11 and 1.0 side by side in one Worker. The "gradual" part lives in two places: (1) the schema migration off the removed `Type` export can be done file-by-file *after* the bump, because pi-ai's `Type` and valibot coexist on 1.0; (2) the new 1.0 surfaces (Channels, observability, typed errors) are additive and each ships on its own. A throwaway spike runs first to convert the unknowns into a concrete task list before we touch `main`.

**Tech Stack:** Flue 1.0 (`@flue/runtime`/`@flue/sdk`/`@flue/cli`), Cloudflare Workers + Durable Objects, `agents` SDK, `@cloudflare/sandbox`, valibot (schema), Hono (`.flue/app.ts`).

## Global Constraints

- Target version: `@flue/runtime`, `@flue/sdk`, `@flue/cli` all at `1.0.0-beta.1` (pinned exactly — it's a beta; no caret).
- Source layout stays `.flue/` (1.0 supports it as priority-1 source root — do **not** relayout to `src/`).
- `agents@^0.15.0` already satisfies the 1.0 peer (≥0.14.1). Do not downgrade.
- `valibot@^1.4.1` is already a direct dep — the valibot schema path adds **no** new dependency.
- Compatibility date in `wrangler.jsonc` is `2026-06-09`; bump only if the spike's `flue dev`/build demands it.
- Do **not** rewrite or reorder existing `wrangler.jsonc` migration entries (Cloudflare requires an append-only DO migration history).
- This is a beta runtime. Nothing merges to `main` until it deploys to a staging Worker **and** survives a turn against realistic Durable Object state.

## Why now (the case for doing it this turn)

The delta is at its smallest it will ever be: the repo touches only **6 Flue symbols**, 5 survive 1.0 unchanged, and the structural wiring (`.flue/` layout, `flue.config.ts`, DO class names, `agents` peer) is already 1.0-compatible. Every feature built on 0.11 between now and later only grows the schema-conversion surface. `1.0.0-beta.1` is now npm's `latest` tag while we're pinned to `0.11.x` — 0.11 is end-of-line.

## Two schema paths (the core decision)

- **Path A — pi-ai-direct (fast unblock):** change the 23 import lines from `@flue/runtime` to `@earendil-works/pi-ai`, add `@earendil-works/pi-ai` as a direct dep. All ~230 `Type.*` calls stay byte-identical. Diff ≈ 24 lines. Relies on `defineTool` accepting pi-ai's JSON-Schema output (1.0 docs: "a raw JSON Schema object is also accepted"). Risk: couples us to a transitive Flue may drop.
- **Path B — valibot (canonical end-state):** rewrite call sites. `Type.Object({...})`→`v.object({...})`, `Type.String({description})`→`v.pipe(v.string(), v.description('...'))`, `Type.Optional(x)`→`v.optional(x)`, `Type.Union`→`v.union`, `Type.Literal`→`v.literal`, `Type.Integer`→`v.pipe(v.number(), v.integer())`. No new dep (valibot already direct, already used in `src/agent-runs/`). Removes pi-ai coupling. Bigger diff; the 99 `Type.String({description})` → pipe rewrites are the bulk.

**Recommended sequencing:** Path A *during* the bump (Phase 1) for the smallest possible atomic change, then Path B *gradually* file-by-file (Phase 2) — both coexist on 1.0, so there's no big-bang. The spike (Phase 0) proves Path A actually validates at runtime before we commit to it.

## Decisions (Shyang's call)

- **Decision 1 — schema path & timing.** Recommended: Path A in Phase 1 (smallest atomic diff), Path B gradually in Phase 2. Alternative: do the valibot rewrite (Path B) *during* the bump to avoid ever adding the pi-ai dep — bigger atomic change, but one-and-done. Default to A unless you'd rather not touch the 23 files twice.
- **Decision 2 — production cutover version.** Do the spike + Phase 1 + staging now (the prep is cheap while the delta is small), but choose where the *production* deploy lands: (a) cut over on `1.0.0-beta.1` now, or (b) hold the green branch and cut over when `1.0.0` stable ships. Option (b) honors both "migrate now" and "don't ride a 2-day beta into prod" — prep is done, only the final flip waits. Recommended: (b), unless a 1.0-only capability (e.g. Channels) is needed sooner.
